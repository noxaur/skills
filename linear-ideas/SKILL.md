Each idea is an outcome the user has in mind. File it so they can pick it up months later with no memory of this conversation.

## Where it goes

Use the Linear MCP server. File in the team and project the work belongs to, and ask the user when that is unclear. Set state **Backlog** and label **Idea**, and leave priority unset. If the team has no Idea label, create it. Ideas skip Triage.

## One ticket per outcome

- Title: the outcome as one short statement.
- `## Outcome`: the end state the user described, in their words.
- `## Details`: everything else the user said that is needed to explain that outcome, such as why, examples, constraints and what they ruled out. Spell out references like "the thing from before" so the ticket stands alone.

Write only what the user said. Do not add open questions, implementation plans, user stories or acceptance criteria they did not state, because your guesses at these are often wrong. When you can't tell what outcome the user means, ask before you file.

Search the team for an existing ticket first. If one already covers the outcome, add the new details there. Mark tickets from the same session as related, then reply with their links.
